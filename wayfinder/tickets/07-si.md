## Resolution (closed)

Pure data change, as predicted: one CASES row, zero code changes.

**CASCI physics: textbook-perfect.** ROHF/cc-pVDZ = −288.84643692 Eh.
Ms=1: ³P ×3, ⟨L²⟩ = 2, ||[H, Lz]|| = 0 exactly. Ms=0: ³P×3 < ¹D×5 < ¹S×1
with ⟨L²⟩ = 2/6/0, commutators ~1e-14. The first p-type core ([Ne] incl.
2p⁶) folds exactly — `_spherical_average_density` proved generic (it
m-averages within every same-l shell pair).

**Finding 1 — CASSCF/SA-CASSCF escape the 3p shell for Si** (hence
`run_casscf=False, sa_weights=None` in the Si row). Single-root CASSCF ran
to an ³S-like solution with E ≈ −10.17 Eh and ⟨L²⟩ ≈ 0.02: the optimizer
rotated s-character into the active window instead of staying in 3p²
(max|dE| vs PySCF = 4.91 Eh — the analysis space and the optimized space
disagree, so the reported absolutes are meaningless for a runaway run).
SA over the 3 × ³P weights also collapsed (three degenerate L = 0 roots).
This is the CASSCF multi-solution class anticipated for TMs in ticket 08 —
it arrives already at the 3s²3p² atom, because 3s is energetically close
enough for the optimizer to escape. NOT a code bug: the CASCI stages prove
the operator construction is exact. AGENTS.md fact 13 records it.
Follow-up candidate (fog): a CASSCF-stability ticket (CASCI-seeded start
or inter-shell-frozen rotations) if orbital optimization matters beyond
carbon.

**Finding 2 — CASCI max|dE| scale**: 3.1e-4 Eh for Si vs ~1e-7 for carbon:
the folded-core vs actual-core discrepancy grows with the core (12 e⁻ incl.
2p⁶ here vs 2 e⁻). Same documented cause (AGENTS.md fact 5), fine at this
order; the term tables and degeneracies are exact regardless.
